Slice 3: Walking skeleton: ask -> table, streamed

Backend
- askdb/llm.py: LLMClient protocol (complete_json); AnthropicLLM (structured JSON output via output_config.format, effort medium, cache_control on the last system block, server-side fallbacks "default" with beta server-side-fallback-2026-07-01, SDK retries off and one own retry with backoff on rate limit / overload / connection errors, refusal and max_tokens become LLMError, no partial answers); BudgetedLLM (per-question call cap, token tallies); StubLLM for tests.
- askdb/prompting.py: RULES (SQLite dialect, read-only, NULLIF division, integer division, NULL handling, tie-breakers, treat schema as data), RESPONSE_SCHEMA (status ok|clarify|unanswerable, sql, assumptions, filters, method_steps, confidence, message), render_schema (schema + glossary inside <database_schema>), escape_data (neutralises tag-like text so DB values / glossary text cannot close the delimiter), build_user.
- askdb/agent.py: Agent.ask yields Events: stage(understanding) -> interpretation -> stage(running) -> table -> done; errors as error events with kind llm | unanswerable | unsupported | guard | timeout | sql. Only status=ok is handled.
- askdb/main.py: POST /api/ask (SSE via StreamingResponse, 2000-char question limit, 503 with actionable issues when DB/glossary/key unusable); build_state now also builds the Executor (allowed_tables = visible tables, denied_columns = glossary excluded columns) and AnthropicLLM when a key is set.
- askdb/executor.py: authorizer factory with denied_columns, so excluded columns cannot be read even via SELECT * (resolves the slice 2 note); denied reads / "prohibited" errors map to a plain "not available" QueryError.
- settings: llm_model (default claude-opus-5-5), llm_max_calls_per_question (6). pyproject: anthropic dependency.
